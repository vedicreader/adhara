# Working in this repo

Rust first. `src/` is the source. The Python package (`python/adhara`) and the Swift package (`swift/`, `Package.swift`) are thin layers over it. `src/tables.rs` is generated by `scripts/gen_tables.py`; never edit it.

## The one rule

adhara gives litesearch's results. The folds equal `litesearch/sanskrit.py` on every word of the test corpus. The tokens equal litesearch's chain, with one apsw quirk documented in `RESULTS.md`. `adhara_hybrid` returns the rows of litesearch's `search` in the same order. A faster way that changes a result is a bug. The tests in `tests/` compare with litesearch directly.

## Three parts

- `fold.rs`: the port of sanskrit.py. No SQLite.
- `tok.rs`: the FTS5 tokenizer `adhara`. Porter goes outside it (`porter adhara`), as litesearch puts porter outside its chain.
- `hybrid.rs`: the `adhara_hybrid` table function. It reads litesearch's schema: `<store>`, `<store>_fts`, `usearch_indices`.

## Builds

- `--features python`: the Python module. The same file is the SQLite extension (`sqlite3_adhara_init`).
- `--features static`: SQLite built in, for Swift (`adhara_register`).
- A new tokenizer name, not new behaviour under an old name. FTS5 tokenizes old content again on delete, so a changed token corrupts an index.

## Numbers

Every speed claim has a row in `RESULTS.md` and a script in `bench/`. Change the number before the claim.
